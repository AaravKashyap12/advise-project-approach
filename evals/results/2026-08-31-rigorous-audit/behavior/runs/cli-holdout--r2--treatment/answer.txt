Assumption: with Python standard library only, use filesystem timestamps (`st_mtime`) as the rename source unless your filenames already contain reliable dates, because stdlib alone is not a robust EXIF parser.

1. Build a `plan` mode that scans the target folder, derives each photo’s proposed new name, detects collisions, and writes a CSV manifest with `original_path, proposed_name, timestamp_used, conflict_status` without changing any files. Acceptance behavior: running the tool on your 500-photo folder produces a manifest and reports `0 files renamed`. Focused check: manually inspect 20 mixed files in the CSV and confirm the proposed names match the dates you expect before proceeding.

2. Add an `apply` mode that only consumes a previously generated manifest, skips any row marked conflicted, renames with `os.replace` in a deterministic order, and writes a rollback CSV mapping `new_path -> original_path` as it succeeds. Acceptance behavior: after a small trial on a copied test folder, filenames change exactly as listed in the manifest and the rollback file can restore them. Focused check: run `plan` then `apply` on 5 copied photos, confirm the names changed correctly, then run rollback and verify every original name returns.

If more than a few sampled files show wrong dates because filesystem timestamps are unreliable, this standard-library approach is the wrong one and you should either switch the date source rule or allow an EXIF-capable dependency.
