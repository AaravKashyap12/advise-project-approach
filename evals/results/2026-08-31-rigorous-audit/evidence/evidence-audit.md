## Verdict

**Partial evidence of development progress; insufficient evidence of repeatable comparative advantage or cross-host execution.** The final saved narrow answer really is shorter than v0.7.0, contains exactly three primary steps, and makes acceptance behavior explicit. **Confidence: High.** Locations: [v0.7.1 baseline-first grader:3](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/results/2026-08-24-v0.7.1-ab-grader-baseline-first.txt#L3), [treatment-first grader:3](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/results/2026-08-24-v0.7.1-ab-grader-treatment-first.txt#L3), and [A/B report:31](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/results/2026-08-24-v0.7.1-ab-report.md#L31).

Their concluding paragraphs explain only a few differences. The repository's [published rubric:19](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/README.md#L19) instead defines named criteria and [requires pass/partial/fail/not-applicable with evidence:30](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/README.md#L30). The v0.7.0 graders use eight criteria, so their numbering cannot supply the missing ten-criterion mapping either.

If the ten numbers are meant to map directly to the published rubric, this no-research narrow answer would need explicit treatment of source/comparable criteria, not an unexplained maximum. If they map to a special narrow rubric, that rubric is missing. A reader cannot determine which interpretation was used or whether the same rule was applied to both candidates.

**Consequence:** The advertised perfect scores cannot be independently reconstructed, and the score margins cannot be compared to earlier runs. Preserve the precise grader input and per-criterion evidence with this result; until then, report the two observed preferences separately from a validated score.

### E04. P2 / Medium: A proposed concurrency probe is overcredited as deterministic proof

**Confidence: High for the evidence gap; no claim about an implemented booking system.** Locations: [v0.7.1 grader rationale:17](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/results/2026-08-24-v0.7.1-ab-grader-baseline-first.txt#L17), [final treatment:1](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/results/2026-08-24-v0.7.1-ab-treatment.txt#L1), and [case assertion:121](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/cases.json#L121).

The saved answer recommends "two simultaneous booking attempts" and checking that only one succeeds. It supplies an expected outcome but no synchronization point, controlled overlap, or equivalent guarantee that both attempts reach the vulnerable transaction window. Two requests issued together can execute serially and pass despite a race defect. The baseline's equivalent proposal at [line 7](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/results/2026-08-24-v0.7.0-ab-baseline.txt#L7) is also explicitly called deterministic by the [older grader:5](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/results/2026-08-24-v0.7.0-ab-grader-baseline-first.txt#L5).

The final answer's other checks are useful, concrete starting points, but "replay twice" at [line 5](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/results/2026-08-24-v0.7.1-ab-treatment.txt#L5) also leaves concurrency and interruption behavior unspecified. This is not a request to add a full implementation to a short answer: the defect is crediting an underspecified probe as already deterministic. A failing invariant also does not uniquely prove the answer's diagnosis that the "domain boundary is wrong"; a local transaction bug could cause it.

**Consequence:** The grading rewards the language of proof more strongly than the proposed test design supports. Distinguish a useful falsification target from a reliably race-exercising test, and grade both candidates by that same distinction. No concurrency test was run in this audit.

The runtime expressly permits disclosed, provisional fallback when browsing is unavailable at [SKILL.md:233](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/skills/advise-project-approach/SKILL.md#L233) and [line 298](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/skills/advise-project-approach/SKILL.md#L298). General guidance to record research access does not define how to score that branch. There is also a fairness boundary in the narrow case: [the user prompt:117](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/cases.json#L117) asks for three implementation steps and early architectural feedback; the [all-steps-add-product-behavior criterion:125](https://github.com/AaravKashyap12/advise-project-approach/blob/c4885d2f0155fbf912f3ad2489ac75d637545ba1/evals/cases.json#L125) is a skill-design preference, not an explicit user demand. The baseline's dedicated integration-test step can satisfy the user while failing that narrower preference. That criterion can measure instruction compliance, but should not silently stand in for general answer utility.

**Consequence:** Score changes can reflect fixture drift, tool access, or adherence to a preferred answer form rather than a behavioral regression or improvement. Version the relevant fixtures/conditions and distinguish skill-contract scores from user-outcome judgment; the present corpus does not make those comparisons stable.
