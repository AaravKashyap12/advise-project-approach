For this app, use Django server-rendered templates unless you already have a real SPA requirement. With 20 internal users, a two-week CRUD-heavy timeline, and strong Python but no React experience, templates fit better because they let you ship forms, auth, table views, validation, and permissions in one stack with less setup, less frontend state management, and fewer integration points to debug; a separate React SPA mainly buys you richer client-side interactions and a more app-like UI, but it costs you time in frontend architecture, API design, auth/session handling, form state, and build tooling right when schedule risk is highest. This becomes the wrong choice only if the UI must support highly interactive offline-like workflows, complex live filtering/editing, or shared frontend patterns that Django templates would clearly fight.
