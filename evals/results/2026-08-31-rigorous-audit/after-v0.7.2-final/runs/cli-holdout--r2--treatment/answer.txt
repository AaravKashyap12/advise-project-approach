Assumption: photo dates come from filesystem timestamps or a date already available locally, since external metadata libraries are out of scope.

1. Build a `--dry-run` pipeline that scans a chosen folder, derives each target name, detects collisions before any write, and prints a deterministic rename plan like `old -> new` plus a summary of `would rename`, `would skip`, and `conflicts`. Acceptance: on a disposable test folder, the command produces the full plan without changing any filenames. Focused check: include at least one duplicate-date case and one already-correct filename, then confirm the output marks the duplicate as a conflict and the existing correct name as skipped.

2. Add the real rename mode so it only executes from that validated plan and refuses to overwrite an existing destination by using an atomic no-clobber operation at the write boundary, aborting or skipping on any conflict instead of replacing files. Acceptance: on a disposable copy of a few test photos, successful entries are renamed, pre-existing destination names remain untouched, and the tool reports exactly which files were skipped or failed. Focused check: after previewing, manually create one of the planned destination filenames before running the real command; the tool should refuse that rename without data loss, which proves the safety check works against stale previews.
