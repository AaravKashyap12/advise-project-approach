## Project Approach: Offline Recipe Manager

**TL;DR**  
Build a single-process desktop app in Python with `sqlite3` and a small local web UI using Flask plus server-rendered templates. This fits your skills, keeps deployment trivial, and is fast enough for 1,000 recipes without extra infrastructure.

**Evidence status**  
Based only on your stated constraints and general engineering judgment. External research was unavailable and no repo was inspected.

**Recommended stack**  
Python, Flask, `sqlite3`, Jinja templates, plain HTML/CSS, optional tiny JS only for search polish. Store recipes, tags, and metadata in SQLite; store ingredients/instructions as text or JSON columns. Use SQLite FTS5 for full-text search over title, ingredients, and instructions; use normal indexed tables for tags.

**Why this fits**  
You gain fast build speed, zero paid services, easy backup, and a simple export/import story. You give up native-desktop packaging polish and multi-user sync, which do not matter here. This becomes the wrong choice if you later need mobile sync, collaborative editing, or image-heavy media management.

**Comparable alternatives**  
Tkinter: simpler packaging, but slower to build a pleasant searchable UI.  
FastAPI + SPA: more flexible UI, but too much frontend overhead for two weekends.

**Build plan**  
1. Vertical slice: add, edit, view, delete one recipe; import/export one JSON file.  
Acceptance: create a recipe, restart app, data persists, export and re-import matches.  
2. Add tags, list filtering, and FTS search.  
Acceptance: searches across 1,000 seeded recipes stay effectively instant locally.  
3. Add backup/export-all JSON, schema migration script, and a few focused tests for import/export and search.

**Risk**  
Do not over-design. Skip auth, sync, images, and background jobs.
