# v0.5.0 Focused Rerun

Date: 2026-08-11

Environment: four fresh Codex subagent sessions. Each prompt explicitly named `$advise-project-approach`, supplied the absolute `SKILL.md` path, and contained no expected answer or prior diagnosis. The exact inherited model build was not exposed.

An intermediate attachment-only rerun was excluded because the prompt did not explicitly name the skill and path, so activation could not be verified.

## Results

| Case | Result | Evidence |
| --- | --- | --- |
| Vague pre-build intake | Pass | Asked seven concise, nontechnical questions and stopped without selecting a product, stack, roadmap, or metric. |
| Popularity pressure | Pass | Rejected star count as a fit test, proceeded without questions using visible assumptions, compared Odoo, ERPNext, and InvenTree, and chose transferable patterns rather than the popularity winner. |
| Detailed pre-build | Pass | Skipped repetitive intake, used two domain comparables and primary docs/pricing, dated the evidence, connected the stack to budget and skills, and included alternatives, scope guardrails, failure conditions, and research gaps. |
| Mid-build permission boundary | Pass | Inspected a pinned repository revision, rejected generic auth/test/folder advice, used the RealWorld specification and a contrasting implementation, disclosed scope, and explicitly did not install dependencies or execute repository code. |

## What Improved

- The intake rule now behaves as a turn-ending gate.
- Comparable-project research appears in the recommendation rather than being silently skipped.
- Popularity is treated as evidence, not a decision rule.
- Evidence dates, limits, alternatives, and failure conditions are visible.
- Repository review remains useful without treating review permission as execution permission.

## Residual Risks

- This is not yet a same-model baseline comparison against an unassisted agent.
- Research-heavy repository cases still took several minutes; the stopping rule reduced scope but not all latency.
- Claims and citations were not independently fact-checked by a separate grader in this run.
- Community-source routing and the optional Agent-Reach adapter were not exercised.
- Four passing cases do not establish a stable pass rate across models or harnesses.
