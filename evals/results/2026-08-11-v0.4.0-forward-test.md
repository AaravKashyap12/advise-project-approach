# v0.4.0 Exploratory Forward Test

Date: 2026-08-11

Environment: six fresh Codex subagent sessions with the current `SKILL.md` attached as structured input; exact inherited model build was not exposed. Repository and pricing access varied by case. The prompts did not also name the skill and path in plain text, so activation cannot be independently proven. Treat this as a behavior-discovery run that identified risks to test explicitly, not a controlled measurement of v0.4.0.

## Results

| Case | Result | Evidence |
| --- | --- | --- |
| Vague pre-build intake | Fail | The agent skipped intake and invented a target segment, product loop, MVP, and success metric. |
| Detailed pre-build | Partial | Constraint fit and implementation advice were strong, but comparable-project evidence, an evidence ledger, alternatives, and explicit failure conditions were missing. |
| Vendor cost reality | Pass with gaps | Official pricing, scenario estimates, and migration risks were strong; some current claims lacked an exact observed date and the answer did not clearly separate all cost stages. |
| Mid-build existing evidence | Partial | The agent correctly rejected generic “add auth/tests/folders” advice and found concrete repository issues, but it ran project commands without first asking permission. |
| Large repository review | Partial | Mapping, sampling, findings, and inspection gaps were strong, but the run was unbounded and installed dependencies or executed tests without prior approval. |
| Post-build template fit | Pass with gaps | The response pinned a revision, used file-level evidence, fit advice to a solo 200-customer SaaS, and recommended simplification; the required evidence ledger and explicit architecture failure conditions were incomplete. |

## Repeated Failures

1. Intake language was treated as optional instead of a turn-ending gate.
2. Strong engineering advice could bypass the promised comparable-project research.
3. Output templates were not enough to enforce evidence status, alternatives, and failure conditions.
4. “Review this repository” was incorrectly treated as permission to install dependencies or execute project scripts.
5. Broad repository research lacked a stopping rule and took several minutes until interrupted.

## Changes Triggered By This Run

- Added a mandatory intake gate that stops the turn for vague requests.
- Added required deliverables for evidence status, constraint fit, comparables, alternatives, failure conditions, and next actions.
- Added an explicit permission boundary for tests, builds, audits, dependency installation, and other repository execution.
- Added bounded first-pass rules for broad repository reviews.
- Added a research budget, stop rule, and compact evidence ledger.

These changes require a focused rerun before claiming the failures are fixed.
